# ADR-0002: arm64 in CI — GitHub's native arm64 runner (ubuntu-24.04-arm)

- **Status:** Accepted (tried and proven on a trial branch)
- **Date:** 2026-10-09
- **Related:** `.github/workflows/ci.yml`; [threat model](../threat-model.md) KT-14;
  [architecture](../architecture.md#performance-and-resilience)

## Context

Koru requires CI to build and test it on both x86_64 and arm64. A `cross` + QEMU fallback applies
if GitHub's arm64 runner (`ubuntu-24.04-arm`) cannot be used. Conditions: no paid feature, larger runner or billing setting is used; Actions minutes are not
wasted.

Building Koru has a special requirement: Pulsar's eBPF probes are compiled with clang at build time
(ADR-0001 outcome 3). `cross` images have no clang; a full build and test under QEMU is many times
slower than a native build.

## Options

1. **Native arm64 runner (`ubuntu-24.04-arm`)**, a standard GitHub-hosted runner (counts against
   the free plan's minutes). Build and tests run on real arm64 hardware with the same steps as
   x86_64.
2. **`cross` + QEMU** on an x86_64 runner: needs extra image configuration (clang, llvm, arm64
   SQLite). Tests run in user-mode emulation; time and minute cost are high.

## Trial (try first, prove the result)

The workflow ran on a separate trial branch (commit `857f2d2`) before entering the protected set:

- Run `37978516722` (2026-10-09): all three jobs succeeded.
  - `build and test (x86_64)`, `ubuntu-24.04`: 4 min 14 s.
  - `build and test (arm64)`, `ubuntu-24.04-arm`: 4 min 5 s. The runner was assigned immediately; `uname -m` → `aarch64`; rustup is preinstalled in the image.
  - `supply chain and secret scan (x86_64)`: 6 min 2 s (including the first install of cargo-audit
    and cargo-deny; later runs come from cache).
- All three test groups passed on arm64 and x86_64: schema 19, translation 11, dependency check
  14. That the translation tests also pass on x86_64 shows the samples recorded on aarch64 decode
  architecture-independently (ADR-0003, flags).

## Decision

**Option 1: the native arm64 runner `ubuntu-24.04-arm`.** `cross` + QEMU are not used. The
workflow (`.github/workflows/ci.yml`):

- `test` matrix: `ubuntu-24.04` (x86_64) and `ubuntu-24.04-arm` (arm64). Steps: build,
  `cargo test --workspace --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  `cargo fmt --all --check`.
- `supply-chain` (x86_64 only): `cargo audit`, `cargo deny check`,
  `cargo xtask dependency-check`, gitleaks (`git` and `dir`). These checks are
  architecture-independent: `deny.toml` checks both Linux targets, `xtask` reads the graph without
  platform filtering. Running them twice adds nothing but minutes.
- Security settings (KT-14):
  - All actions pinned by commit SHA: `actions/checkout` v7.0.1, `actions/cache` v6.1.0.
  - `permissions: contents: read`; checkout does not persist credentials (`persist-credentials: false`).
  - No secrets are used; fork pull requests receive no secrets.
  - cargo-audit 0.22.2 and cargo-deny 0.20.2 are installed pinned with `cargo install --locked`
    (cached). gitleaks 8.30.1 runs from the official binary, SHA-256 verified; gitleaks-action is
    not used.
- Minute savings:
  - Triggers only on push to `main` and pull requests to `main`.
  - A new push on the same branch cancels the old one (`concurrency`).
  - The cargo registry and `target/` are cached; there is no needless matrix.

## Consequences

- arm64 builds and tests run on real hardware; no QEMU emulation.
- If the native arm64 runner is later removed or priced, this ADR reopens; the
  fallback is `cross` + QEMU (a custom image with clang is needed).
- `.github/workflows/` is in the protected set. The workflow was taken into the repository exactly as
  it stood on the trial branch; it is only extended, never relaxed (see
  [CONTRIBUTING.md](../../CONTRIBUTING.md#protected-files)).
