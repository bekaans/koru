# ADR-0009: End-to-end scenario list, golden data and measurement method

- **Status:** Accepted. **Date:** 2026-10-17.
- **Related:** [detection quality and measurement](../architecture.md#detection-quality-and-measurement) (measurement definitions are fixed, never changed), ADR-0005, ADR-0007

## Decisions
1. **List freeze:** scenarios live in the `lab/scenarios/list.toml` data file; the runner code reads the list. The list is committed together with this ADR and is not changed after measurement (a change needs a maintainer decision). From the Atomic Red Team Linux techniques, those within Koru's scope (T1552.001, T1552.004, T1552.003, T1083, T1005, representable by decoy/breadcrumb access) are chosen; out-of-scope techniques are listed with rationale in `lab/scenarios/out-of-scope.md` and do not count toward the 100. The 100 scenarios are a deterministic selection from 9 decoy/breadcrumb classes × read methods (cat, head, grep, cp, dd, base64, python3, tar, awk, xargs) × actor contexts (human shell, AI-agent chain, MCP-server chain, shell-less script, podman container); every class has at least 8, the AI context at least 20, containers at least 5 scenarios.
2. **Runner:** `lab/scripts/scenarios.py` (python3 in the VM, tomllib), using the `live_detect` agent mechanism (the pattern used by the detection tests). Each scenario runs in turn; a finding is matched by target path + the scenario time window. Result table: scenario, expected, found (finding/actor/technique), status.
3. **Golden data:** finding events the agent produces during the run are written to `data/golden/synthetic/`, legitimate-phase events (agent `--event-output`) to `data/golden/legitimate/` as JSONL. `crates/koru-detect/tests/golden_data.rs` replays them in CI without a VM: every synthetic record yields at least one finding, legitimate records zero findings.
4. **AI attacker (an LLM agent):** selection and running depend on the `KORU_LAB_LLM_*` `.env` gate; when the gate opens, the candidate (license + maintenance) is entered into this ADR as an additional decision. While the gate is closed, the AI context is proven with the signature-matching process-chain simulation of the detection tests; LLM-run evidence is taken separately.
5. **Measurements:** CPU/RAM/latency per the definitions in [detection quality and measurement](../architecture.md#detection-quality-and-measurement); for latency a local ntfy (a fake in-VM HTTP receiver timestamp) is used. The metrics report is `docs/reports/metrics.md`, written by the generator script, never edited by hand.
6. **Demo:** `lab/lab.sh demo` produces `docs/demo/koru-demo.cast` with asciinema in the VM (asciinema is added to the lab setup).
